Метапоиск по базам судебной практики

Инструмент формирует запрос и открывает поиск каждой базы в вашем браузере. Сам он сайты не опрашивает: поиск выполняете вы, как обычный пользователь. Где точный формат ссылки известен, запрос подставляется в адрес; в остальных случаях он копируется в буфер обмена, чтобы вставить его в строку поиска базы (Ctrl+V).

Базы

Бесплатные базы — открываются сразу. Платные — нужна подписка; в них есть собственные сохранённые запросы с e-mail-оповещениями: полнотекстовый мониторинг без парсинга.

Мои источники

Добавьте любую базу судебной практики вручную. Шаблон поиска — адрес страницы результатов, где вместо запроса стоит {q}, например https://www.example.org/search?query={q}. Шаблон можно взять из адресной строки после любого поиска на сайте. Без {q} адрес просто откроется, а запрос скопируется в буфер. Если у источника есть официальная RSS-лента, её можно передать в мониторинг. Правила те же: только https, проверка robots.txt, решение оператора, HKLII исключён.

Добавить ленту

Правила опроса. Только https-ленты с хостов legalref.judiciary.hk, www.hkcfa.hk, www.judiciary.hk; HKLII исключён. Одна лента — не чаще 1 раза в 10 минут (настраивается), с ETag/If-Modified-Since. Тексты решений не скачиваются. Если robots.txt запрещает путь ленты, лента не опрашивается, пока оператор не отметит «Допускаю опрос»: решение остаётся за вами.
Факт на 27.10.2026: robots.txt legalref.judiciary.hk — User-Agent: * / Disallow: /, то есть запрет для всех программ на весь сайт, включая адреса RSS-лент. При этом Судебная власть публикует ленты для подписки в RSS-ридерах (страница RSS на hkcfa.hk). Опрос лент LRS возможен только по вашему решению — отметка «Допускаю опрос». Без неё мониторинг LRS не работает.

Профили поиска

Параметры отбора для мониторинга RSS и анализа документов. Поиск без учёта регистра по заголовку, описанию, номерам дел и NCN. Слова разделяются «;» или переносом строки; допускаются фразы и китайские иероглифы. При подключённом сервере профили хранятся на нём, иначе — в этом браузере.

Рассылка выполняется локальным сервером (вкладка «7. Установка»).

SMTP и получатели

Для Gmail: smtp.gmail.com, порт 465, SSL, вход — адрес Gmail, пароль — пароль приложения Google (не основной пароль). Пароль хранится только на вашем компьютере, в папке данных сервера (файл secret.json, права 600 на Linux/macOS).

Расписание

В дайджест попадают новые, ещё не отправленные решения по профилям с отметкой «в рассылку»: дата, лента, заголовок, номер дела/NCN, ссылка на LRS, сработавшие слова. Тексты решений в письмо не включаются.

Анализ загруженных решений

Откройте решения на LRS, HKLII или в подписочной базе вручную, сохраните (PDF, DOCX, HTML, TXT) и загрузите сюда. Обработка идёт только в браузере, файлы никуда не отправляются. Извлекаются суд, NCN, номера дел, дата, состав суда; поиск — по словам или профилю, с фрагментами текста.

Ссылки на подтверждающие страницы

    Установка локального сервера

    Нужен Python 3.8+, дополнительные пакеты не требуются. Сервер читает RSS-ленты, хранит профили и найденные решения, отправляет письма. Работает только на вашем компьютере: адрес 127.0.0.1:8767.

    Порядок

    1. Скачайте все четыре файла в одну папку.
    2. Windows: запустите start_hkcl.bat. Linux/macOS: bash start_hkcl.sh. Вручную: py -3 hk_caselaw_server.py или python3 hk_caselaw_server.py.
    3. Откройте http://127.0.0.1:8767/. Страница на GitHub Pages тоже подключится к серверу (Chrome/Edge/Firefox; Safari блокирует запросы к localhost со страницы https).
    4. «2. Мониторинг RSS»: добавьте ленты со страницы подписки LRS и проверьте статус robots.txt.
    5. «3. Профили поиска» и «4. Рассылка»: задайте параметры и SMTP, отправьте тестовое письмо.

    Параметры запуска

    --port 8767                  порт (по умолчанию 8767)
--auto-check 6               автопроверка каждые 6 часов
--proxy http://proxy:3128    корпоративный прокси
--cafile corp-ca.pem         сертификат прокси, подменяющего TLS
--allow-origin https://...   доп. адрес страницы, которой разрешён доступ к серверу
--data ./hk_caselaw_data     папка данных
--check-once                 однократная проверка + рассылка (для планировщика задач)

    Расписание без постоянно запущенного сервера

    Windows (Планировщик задач, ежедневно в 08:00):
schtasks /Create /SC DAILY /ST 08:00 /TN HKCaseLaw /TR "py -3 C:\HKCL\hk_caselaw_server.py --check-once"

Linux/macOS (cron, ежедневно в 08:00):
0 8 * * * /usr/bin/python3 /opt/hkcl/hk_caselaw_server.py --check-once

    При --check-once письмо уходит, только если в «Рассылке» включено «отправлять дайджест после автопроверки».

    Что инструмент не делает

    • Не скачивает тексты решений и не обходит сайты: только RSS-ленты, изданные для подписки, и ссылки для ручного перехода.
    • Не обращается к HKLII автоматически: политика HKLII запрещает автоматических агентов для судебной практики.
    • Не входит в Westlaw, Lexis+ и vLex: их оповещения настраиваются в самих сервисах.
    • Не делает правовых выводов: отбирает материалы для оператора.
